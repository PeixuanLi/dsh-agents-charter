# 删除优先的常规运维

[English](delete-first.md) | 中文

- 所属层：[L2 — 外部化记忆](../layers/l2-external-memory.zh.md)
- 管辖范围：删除是笔记系统的常规运维——信噪比靠遗忘维持，而不是靠全盘保留。

## 规则正文

[notes README 的「归档与删除」一节](../../../.agents/notes/README.zh.md#archiving-and-deletion)设定了偏好顺序。删除只描述机械或局部改动的已实现笔记——三个文件一起删，入站链接一并修复；实质性决策不会仅因实现规模小就符合删除条件。其他已实现记录只在仍具历史决策价值时才归档，而只要其备选方案、归属边界、否定性保证、持久化或协议语义、安全规则或重新引入条件仍有价值，就让它保持活跃。绝不归档提案——否决它；被否决的笔记只要仍能避免一种可能发生的错误就保留。由经过校准的归档 skill（技能）决定，而不是字数、存续时间或配额。

## 执法

`Convention — the archive gate audits what remains, not what was deleted`。`pnpm run verify-archived-agent-notes` 检查团队选择保留的部分；删除本身是评审判断，由 [archive-agent-notes skill](../../../.agents/skills/archive-agent-notes/SKILL.md) 校准。

## 成本与前提

评审时的删除优先习惯，仅此而已——删除减少维护，而不是增加维护。唯一前提是上面的保留判据，删除因此不会吃掉仍然指引未来工作的理据。

## 移植清单

- 写进评审清单：这次变更是否让某份既有笔记可删？在同一变更中删除它。
- 删除完整三件套并修复入站链接——从不只删一个文件。
- 归档前先跑保留判据：备选方案、归属边界、否定性保证、持久化或协议语义、安全规则、重新引入条件——命中任何一项就保持活跃。
- 绝不归档提案：否决它；被否决的笔记只要仍能避免一种可能发生的错误就保留。

## 失效模式

只存不删的系统随产出线性膨胀：检索成本攀升，直到没有人再搜索笔记，存储存在却不再起作用——保留着，但已经不可用。失败是隐形的，因为每份笔记单看都值得保留。

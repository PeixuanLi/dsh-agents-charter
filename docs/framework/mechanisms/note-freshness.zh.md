# 保鲜义务

[English](note-freshness.md) | 中文

- 所属层：[L2 — 外部化记忆](../layers/l2-external-memory.zh.md)
- 管辖范围：改代码的同一 PR（Pull Request）更新受影响的笔记；改变决策意味着一篇带互链的新笔记，而不是追加变更史。

## 规则正文

两条规则叠加。[AGENTS.md](../../../AGENTS.md#conventions) 要求只有持久的决策理据才写 Agent Note，并在描述该变更的同一 PR 中更新它。[notes README 的「何时需要写一份」一节](../../../.agents/notes/README.zh.md#when-to-write-one)拥有其余规则：更新已经拥有该决策的笔记即满足规则；笔记永远不会被编辑成另一个决策——用新笔记取代它，并让两者保持互链；已实现的笔记与实际交付的内容保持同步，只更新事实（路径、名称、结构），不改决策本身。

## 执法

`Convention — enforced by the review checklist`。没有任何门禁能把笔记与它描述的世界做差异比较；分类、格式与配对门禁守住结构与语言一致性，同一变更规则在评审时守住。

## 成本与前提

每个 PR 一次检索：在写触碰决策的代码之前，先找到拥有该决策的笔记。取代比编辑便宜——新笔记保持干净，旧笔记保留原始记录。

## 移植清单

- 写进 PR 清单：这次变更触碰了已决策的事实吗？在同一 PR 中更新它的笔记。
- 写代码前先找归属笔记：`grep -rl '<topic>' .agents/notes/implemented/`。
- 取代，不追加：改变决策就是一篇与旧笔记互链的新笔记。
- 事实（路径、名称、默认值）随代码更新；决策正文只通过取代性新笔记改变。

## 失效模式

笔记与现实分叉：代码移动了，笔记没有，后来的读者依据陈旧的理据行动，却无从察觉——没有任何东西标记它已陈旧，它读起来仍然像权威。追加变更史是同一种失败换了戏服：历史不断堆积，开头的决策段落悄然腐烂。

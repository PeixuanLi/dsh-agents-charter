# AI produces, humans decide, machines enforce

- Governs: the three powers' authority boundaries are defined by code, not tacit understanding.

## Rule text

This layer's principle has its home in the [framework paradigm](../paradigm.md)'s four assertions, which begin from this layer: collaboration norms become machine-executable constraints, so any agent or human participant is replaceable; the remaining assertions quantify trust, and the gate ends every rule. Root [AGENTS.md](../../../AGENTS.md) is the corpus that carries the split into every session: every participant loads the same short rules, and each rule names the gate that enforces it, so the powers stay separated by what the code executes rather than by anyone's mutual understanding. This layer enforces the three powers; the fourth role — Agent Notes keeping the rationale behind every rule — is the [L2](../layers/l2-external-memory.md) bridge.

## Enforcement

`Convention — this layer's gates and configs are the enforcement`. The principle has no gate of its own: it is enforced wherever it is implemented, and the other cards name the implementations — [weighted review](../mechanisms/weighted-review.md) for the human decision power, the [L3](../layers/l3-machine-verification.md) verification gates for trusting AI output, the [L5](../layers/l5-process-automation.md) workflows for process execution. A power whose enforcement cannot be named is this layer's open finding, not a settled boundary.

## Cost and prerequisites

None for the principle: stating the powers and their boundaries costs only the paradigm text and a resident rule source. Every real cost belongs to an implementation — a review formula, a gate, a workflow — and each implementation is tier-sensitive on its own, which is why the principle ports at every tier while its enforcement does not.

## Team fit

Solo ✓ · Small ✓ · Medium ✓ · Large ✓ — the principle itself ports everywhere; the implementations are tier-sensitive, and each mechanism card states its own fit.

## Porting checklist

- Write the powers and their authority boundaries into the paradigm as numbered assertions, so the split is quotable rather than remembered.
- Carry the split into the resident rule source so every session loads it, not just the onboarding reader.
- Before relying on any power, name its enforcement: a formula, a gate, or a workflow.
- Audit by pointing: for each power, name the artifact that enforces it today; a power you cannot point at is unenforced.

## Failure mode

Boundaries left to tacit understanding drift toward the most active participant, human or agent: whoever produces the most starts deciding, whoever merges the most starts owning, and nothing in the system marks the change. The drift is silent because tacit understanding has no text to violate — which is why this layer defines its boundaries as code.
